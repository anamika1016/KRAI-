# Assistant production setup

The attached production log showed an invalid systemd environment assignment,
followed by provider failures. The later provider status was not logged by the
old code, so its exact cause cannot be determined from that log.

Revoke the API key exposed in that log and create a replacement. Do not paste
keys into chat, source code, or diagnostic output.

On the production host, run `sudo systemctl edit puma` and correct the existing
invalid assignment under `[Service]`:

```ini
[Service]
Environment="OPENAI_API_KEY=REPLACE_WITH_NEW_KEY"
# Optional: model priority list. The assistant tries the next model only when
# the earlier model is unavailable. There are no free OpenAI API models; API
# billing must be active for every model in this list.
Environment="ASSISTANT_MODELS=gpt-4o-mini,gpt-4.1-mini,gpt-4.1"
```

`Environment=` requires `NAME=value`, not a bare key. Save, then run:

```sh
sudo systemctl daemon-reload
sudo systemctl restart puma
sudo journalctl -u puma --since "5 minutes ago" --no-pager | grep '\[assistant\]'
```

Deploy the code first using the normal application deployment, including asset
precompilation. Test a general module question and `Sausar male count August`
while signed in. Confirm counts against the same month's dashboard. Test a
restricted user too. The assistant sends aggregate visible counts and public
module definitions to the configured AI provider; no personal record details.

Errors now distinguish authentication, access, model availability, quota, rate
limits, and invalid configuration. Logs contain only status and a fixed
category. See https://developers.openai.com/api/docs/guides/error-codes .

Live context covers visible farmer/village/ICS totals and FCO JJ gender counts.
Gender uses dashboard active-JJ logic and is intersected with visible JJ IDs.
The month comes from the latest question, then the page filter, then the existing
dashboard default of the previous calendar month. Farmer totals are all-month
visible totals with FCO and ICS filters if present. Other live reports are not yet connected; the
assistant must guide the user to the relevant report rather than invent values.


## Chat and Excel

The responsive widget includes quick prompts, a new-conversation button, an
Excel report picker with search, and inline download links. Escape closes it.
Common greetings, exact module help, project summary, JJ gender questions and
Excel requests run locally, without requiring an AI API key. Complex answers
still require a working provider; no instant-response guarantee is possible.

Examples: `Project summary`, `Sausar female count July`, `Farmer list Excel July`,
`Training form kya hai`, and `iska Excel do` after a report question.

Excel files are generated by existing report controllers, which enforce their
normal access rules. The new summary download uses the same scoped context as
chat. Module exports are labelled "all visible records" and intentionally do not
claim to apply filters their existing export handlers do not support. Report
exports use their supported query filters and defaults. The picker lists project
modules; a listed report does not grant permission to its data.
